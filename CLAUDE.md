# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Project

Reliq is a mobile walking game. You search the area around you for treasure on a fictional parchment map laid over real GPS. It is vanilla HTML/CSS/JS with WebGL2 and Web Audio, an installable PWA, and ships in English and Polish.

- **Rules:** `docs/reliq-gdd.md` is the source of truth for gameplay.
- **Missions:** `docs/lista-misji.md` lists every mission: title, model, lore, the detail line, distances and the fence price. The user edits it.
- **Plan:** `docs/implementation-plan.md` holds the plan, stage status and decisions.
- **Language:** all three docs are in Polish. The user communicates in Polish, so reply in Polish. Code, comments and commit messages are in English.

## Commands

```sh
node scripts/serve.mjs 8137   # dev server with Cache-Control: no-store (npm run serve)
node --test                   # unit tests (npm test)
```

- **No build:** there is no build step, bundler or package to install. Files are served as-is as native ES modules.
- **Tests:** they live in `tests/*.test.js` and use `node:test` and `node:assert/strict`.
- **Dev URL:** open `http://127.0.0.1:8137/`.
- **Generated files:**
  - `sw.js` is generated by `node scripts/build-sw.mjs`. Rebuild it whenever a file is added or removed, or `VERSION` in `js/version.js` changes. `tests/pwa.test.js` fails if it is stale.
  - Icons come from `node scripts/make-icons.mjs`.
  - Models in `js/render/models/` come from the Blender scripts (see below).
- **Releases:** bump `VERSION`, rebuild `sw.js`, run the tests. `changelogs.md` (Polish) collects the changes under the upcoming version as they land; date that section on release. The service worker is cache-first, so players only see new code under a new version.
- **Dev mode** (`DEV` in `main.js`): on localhost or with `?debug=1`. It enables the debug panel, the simulator choice and the time-warp clock offset.
- **URL switches:**
  - `?gps=sim|real` picks the location source.
  - `?inspect=2[&w=360&h=640]` renders at 2× density, scaled 2×, optionally at a given phone size.
  - `?sw=1` registers the service worker on localhost. Unregister it afterwards: it is cache-first.

## Hard constraints

- **Zero dependencies, no build step.** No frameworks and no npm packages at runtime. External scripts are not allowed: the game must work fully offline, and fonts are self-hosted in `assets/fonts/`.
- **WebGL2 is required.** Shaders are GLSL ES 3.00 strings inside JS modules.
- **Game rules stay DOM-free and tested.** `js/game/*`, `js/core/{geo,noise,rng,store}.js` and `js/gps/{location,filter,compass}.js` must import nothing that touches the DOM at module load, so `node --test` can run them. Time, GPS fixes and randomness are passed in as arguments: `now`, `fix = { lat, lon, acc }`, `motion = { ready, speedKmh }`, `rng`.
- **Every gameplay number lives in `js/game/rules.js`.** When the GDD changes, change it there and update the tests. UI text that mentions a rule number takes it as a placeholder, not as a literal.
- **Every user-facing string goes through i18n.** Use `t('key')` with keys in **both** `js/i18n/en.js` and `js/i18n/pl.js`. Art that contains text, such as notes on junk sketches, must be language-neutral.

## Architecture notes

- **Coordinates.** Positions are stored as lat/lon. Gameplay and rendering use metres in a local frame centred on the Vault (`LocalFrame` in `js/core/geo.js`; x = east, y = north). Terrain noise uses `frame.worldOffset()`, so the same place always looks the same.
- **What you see is what counts.** The searched-area metaball field is defined once in `js/game/field.js` and mirrored in GLSL (`FIELD_GLSL`), so the inked edge on the map is exactly the rule boundary. Biome noise has a bit-identical JS/GLSL twin in `js/core/noise.js`. Change both sides together.
- **Position pipeline.** The source (`GeolocationSource` or `GpsSimulator`) feeds `PositionFilter`, a Kalman filter. The filtered track feeds `LocationTracker` for the 20 s speed check. The needle is drawn at the filtered estimate, and the rules use that same estimate, with accuracy taken from the latest raw reading. Do not compute speed from raw fixes: multipath jumps would block searching.
- **Missions and tombs.** A mission is one artifact in one of eight tiers (`TIERS` and `MISSIONS` in `rules.js`, from `docs/lista-misji.md`); the tier sets the walks and the fence price (`missionDef(artifact)`).
  - `nextMission` offers the lowest tier with missions left, shuffled within a tier by `state.seed` (drawn in `createVault`), so a mission added later just slots in. Missions are numbered in the order played (`nextNumber`); mission, tombs and lost entries carry both `n` and `artifact`.
  - `startMission` clears the searched areas and starts a 7-day clock.
  - Each stage is a walk measured in a straight line from the stage's oldest active search (`stageStart`). It pays out a key shard three times and then the tomb (`missionCheck`, `rollLoot`). There is no break between stages: the search that gives a shard starts the next one.
  - A found tomb stays closed until its gate is opened on site (`openGate`), which puts the artifact into the satchel. The next mission waits until that artifact is stored in the vault (`missionOffer().carrying`).
  - A mission that runs out of time or is abandoned is lost (`state.lost`), with its tomb. Its artifact reaches the fence 7 days later (`fenceOffers`, `buyArtifact`), and a bought one goes straight to the vault; the mission stays in `state.lost` for the notebook.
  - There is at most one closed tomb, and it always belongs to the active mission. The gate screen is `js/ui/gate.js`, its art `js/ui/gate-art.js`.
  - On the map: the ring and target around the stage's start (`seekingZone()` in `main.js`), and the mission tag beside the mission button (`missionBrief()` in `js/ui/notebook.js`, which also holds the mission notebook page).
- **Satchel and deposit.** The UI calls the satchel a backpack (plecak). Coins and the tomb's artifact go into `state.satchel` (`addCoin`, `openGate`); shards belong to the mission.
  - After a find's reveal, `SatchelButton` (`js/ui/satchel.js`) flies its picture into the satchel button (a shard into the mission button), and the count ticks up when it lands. Tapping the button opens `SatchelView`, a card listing what is carried and how far the vault is. While the satchel is not empty the vault pointer pulses.
  - Inside the vault ring, with GPS accuracy ≤ `depositMaxAccuracyM`, `maybeDeposit()` in `main.js` calls `game.deposit()`, which moves everything into `state.coins` / `state.artifacts`. It waits while any other screen is open.
  - Then `DepositScreen` (`js/ui/deposit.js`) plays "Back at the vault": a 3D chest scene (`VaultScene` in `js/render/vault-scene.js`, models from `scripts/blender/chest.py`) on a timeline in scene time, so a tap speeds it up. Coins land commonest first, then the artifact; a summary closes it.
  - The fence buys only coins in the vault (`sellCoin`, `state.money`).
- **Game state.** `Game` in `js/game/game.js` mutates `state` and calls `onChange`. `main.js` saves with a debounce through `Store` (`js/core/store.js`, localStorage, versioned, validated by `migrate()` in `js/game/state.js`). Bump `SAVE_VERSION` when the save shape changes in a way old saves cannot fill with defaults. Until the first release there are no migrations: an older save is set aside under `reliq.save.unreadable` and the game starts over.
- **Clock.** Everything time-based uses `clock.now()` from `js/core/clock.js`. The simulator's time warp and the debug "+1 h" advance it, and the offset is saved under `reliq.dev.clockOffset`.
- **Screens.**
  - **Game menu.** The game always opens on `GameMenu` (`js/ui/menu.js`): Continue (Begin on a first run, which runs the onboarding), Settings and About. The top bar's ☰ button reopens it. It pauses nothing. A returning player's GPS starts behind it, and on a first run location is requested only after Begin and the onboarding.
  - **Vault journal** (`js/ui/journal.js`, opened by the chest in the dock): four tabs, opening on the first. Notebook has handwritten entries for the mission on offer or under way and the past missions (each opens a notebook page, `MissionNotebook.openPage`), Coins has the coins by rarity, Artifacts the artifact shelf, and Fence has money, lost artifacts and coin sales.
  - **HUD.** Top bar: ☰ (with the debug ⚙ beside it in dev mode), logo, GPS accuracy. Dock: vault (chest icon), the search medallion (a lone spade, no label), recenter. On the map: the mission button and its tag in the top left corner, the compass rose top right, the satchel button bottom left. The vault pointer slides along the map border past these buttons (`avoid` in `EdgePointer`).
- **Rendering.** `MapRenderer` draws in passes.
  - **Base layer:** parchment, biomes, graticule and terrain icons from an SVG atlas, the costly part. It lives in two toroidal caches (`BaseCache` in `js/render/base-cache.js`): world pixel (gx, gy) sits at texel (gx mod w, gy mod h), so a pan paints only the strip that came into view (`planStrips`). The sharp cache has a 96 css px margin. During a zoom gesture (`render(..., { zooming })`) it is never repainted: it is stretched, or the coarse cache (half resolution, `parchmentFS(false)` without paper grain) is shown. After the gesture the sharp cache refills a quarter per frame, with the coarse one on screen meanwhile. Strips of one cache share its icon detail level (`iconLevel`), so they meet without seams; keep `terrainIcons` reaching far enough for the tallest icon. The overlay pass samples the cache itself, so there is no separate copy pass.
  - **Per frame:** the overlay (searched areas culled to the view, Vault ring, mission zone around the walk's start, GPS circle), markers, then post-processing: grade, a smooth vignette and film grain.
  - **Frame rate:** `main.js` throttles map frames.
    - 60 fps for fast motion, 30 fps for idle or walking; battery saver halves both.
    - 10 fps behind full-screen overlays (reveal, journal, menu, deposit, satchel card, onboarding, tomb gate).
    - DOM overlays pinned to the map (labels, tooltip, vault pointer) move only in map frames, so they never swim against it on a fast screen.
  - **Low-poly models:** coins, artifacts and the chest are drawn by `ArtifactRenderer` / `VaultScene` with flat shading (see below). Still images for the collection, the fence, the shelf, the satchel and the deposit summary come from `js/render/artifact-thumbs.js`.
- **DOM map overlays.** Graticule labels, region names, tooltips and the vault pointer live in `js/ui/hud.js` and `js/ui/map-ui.js`, and are positioned each frame from `cam.toScreen()`. The camera keeps the player centred in the visible area via `cam.offsetY`, which `resize()` computes from the top bar and dock heights.
- **Debug panel** (⚙, dev mode). It can:
  - set the next find, including a forced shard or tomb, which skips the distance;
  - bring the time limit a day closer, add coins to the vault, six coins to the satchel or money, and put lost artifacts on sale at once;
  - teleport to the gate or to the vault;
  - preview each artifact, or load a new game or the demo world.
- **Art direction.** The look is an "expedition journal": parchment, sepia ink, oxblood red, brass and leather. Fonts are Cinzel, Cinzel Decorative and EB Garamond. Keep new UI consistent with the tokens in `css/app.css` (map, HUD, reveal, deposit) and with `css/screens.css` (onboarding, journal, menu, toast).
  - Reuse the existing SVG art in `js/ui/art.js` (medallion, vault chest, satchel, menu and HUD glyphs), `js/ui/onboarding-art.js`, `js/ui/junk-art.js`, `js/ui/gate-art.js` (the eight gate symbols) and `js/render/icons.js`.
  - Never use names, characters or music from real film franchises.

## Low-poly 3D models

Tomb artifacts, coins and the vault chest are hand-modelled low-poly meshes in the style of the first *Alone in the Dark*: flat-shaded faces in solid palette colours, no textures, a few hundred triangles.

- **Blender:** `E:\Programy\Blender Foundation\Blender 5.2\blender.exe` (5.2 LTS). Run it headless: `blender -b --factory-startup -P scripts/blender/<model>.py`. Scripts use Blender's bundled Python. Do not call a system `python` from the shell for this.
- **Modelling method:** build every vertex and face explicitly with `bmesh` in `scripts/blender/<model>.py`. Use lathe profiles, mirrored halves, insets or extrudes and closed boxes, the way a person models low poly by hand.
  - Do not decimate high-poly or SDF meshes. The user wants deliberate facets, not triangle soup.
  - Start with simple objects. A skull was too hard as a first model.
  - `scripts/blender/shapes.py` saves the repetition: `slab` (a board cut to an outline, with a chamfer), `box`, `lathe`, `face_toward` (a one-sided decal, built after recalculating normals) and `finish`.
  - Keep every part a closed mesh with outward faces (`recalc_face_normals`). The renderers cull back faces.
- **Colours:** one material per palette colour, set as the material's viewport display colour (`diffuse_color`, read as sRGB). Assign them with `face.material_index`.
- **Export:** each model script ends with `export_model(...)` from `scripts/blender/export_model.py`. That writes `js/render/models/<model>.js`, a generated module with `{ palette, verts, tris: [a, b, c, paletteIndex] }`, converted from Blender's z-up axes to the game's y-up. `extra` adds fields such as a `pivot`, and points in it are converted too.
  - Never edit the generated file by hand. Re-run the script instead.
  - Rebuild `sw.js` when a new model file is added.
- **Rendering:** `ArtifactRenderer` in `js/render/artifact3d.js` lights each face once (flat outputs) and renders at `1 / ARTIFACT_PIXEL` of the CSS size. The canvas is upscaled with `image-rendering: pixelated`. It runs in its own WebGL2 context, created lazily. Specular shine scales with the material's brightness, so metal and glaze glint and dark wood stays matte.
- **Artifacts:**
  - **Registering:** add the id to `ARTIFACTS` in `js/game/items.js` and the model to `MODELS` in `js/render/models/index.js`. Give it `artifacts.<id>.name` and `.lore` in both languages, plus an optional `.detail`: a line about how it looks, shown only once it is found, because the mission card shows the lore before then. `tests/i18n.test.js` checks the id, the model and the name and lore. Add the mission to `MISSIONS` in `rules.js` and to `docs/lista-misji.md`.
  - **Sketch:** the mission card and the fence draw the artifact as an ink sketch straight from its mesh (`artifactSketch` in `js/ui/artifact-sketch.js`): outline, creases and colour borders, a sepia wash and hatching. New models get one for free, so check how it reads after modelling.
  - **Preview:** `reveal.viewArtifact(model, { name, desc })` shows it on the reveal screen with an entry spin and drag to turn. In dev mode the debug panel's "Podgląd artefaktu" button cycles through all artifacts.
- **Coins:** all twelve come from one script, `scripts/blender/coins.py`. Each is a lathe profile with an edge, a rim (or a domed face), a sunken field and one simple motif per side (`bust`, `ring`, `hole`, `punch`). There are two colours per metal, raised and field, and hand-struck coins get a seeded lumpy outline. It writes `js/render/models/coin-<id>.js`, collected in `COIN_MODELS` (`js/render/models/coins.js`). `tests/i18n.test.js` checks every coin has one.
- **Vault chest:** `scripts/blender/chest.py` writes three parts that keep their own coordinates (`buildArtifactMesh(model, { fit: null })`): `chest-body`, `chest-lid` and `chest-gold`. The lid and the heap carry a `pivot` (the hinge, the heap's base); `about()` in `vault-scene.js` turns or scales a part about it.
- **Iterating on shape:** for quick checks before export, render a Workbench contact sheet (front, ¾ and top orthographic views) to a scratch PNG. Write each view to a unique temp filename: Windows locks a PNG the user has open in a viewer, and the save fails.

## Gotchas

- `requestAnimationFrame` does not run in a hidden tab. If browser automation shows a frozen game, check `document.visibilityState` before debugging the code. Keep the test tab open between rounds and reload it, because new automation windows tend to open hidden.
- **Testing in the browser:**
  - `main()` exposes the internals as `window.__reliq`: `state`, `game`, `sim`, `clock`, `reveal`, `journal`, `menu`, `deposit` and more.
  - The game opens on the menu, so click `#menu-play` first.
  - Standing inside the vault ring with a full satchel starts the deposit by itself.
  - To watch an animation frame by frame, slow it down, e.g. `__reliq.deposit.speed = 0.25`.
  - Finish a test session with the debug panel's demo world, which also clears the clock offset.
- Serve with `scripts/serve.mjs`, not `python -m http.server`. Python's server lets the browser cache ES modules, so a reload can silently run stale code.
- Inline SVGs share one document, so gradient, filter and clip IDs must be unique across the page. `artifactSketch` numbers its own.
- SVG drawn via `<img>` (the icon atlas, a flying shard) cannot use web fonts and needs an `xmlns` attribute.
- Nothing textured in screen space over the map (stains, grime): it stays put while the map slides under it and gives the effect away.
- `resetGame()` in `main.js` sets `resetting = true` so the save-on-unload cannot overwrite the cleared save. It backs both "Start over" in settings and the debug panel's new game and demo world. Keep that guard when touching saving.
- **No vault yet** (first run, `mode === 'place'`): the map uses a provisional local frame, which is the first GPS fix or the demo spot. `setFrame()` in `main.js` moves the simulator, camera and filter into the vault's frame when it is stamped. `game.toLocal()` only works once a vault exists, so guard with `state.vault`.
- **WebGL context loss:** the map, every `ArtifactRenderer` (reveal coin, reveal artifact, thumbnails) and `VaultScene` rebuild their GPU resources on `webglcontextrestored`. New GPU resources must be created in `init()` / `setup()` so they come back too.
- **Translations:** `tests/i18n.test.js` checks that both languages have the same keys and placeholders, and that every literal `t('key')` or `data-i18n` key exists. Build keys dynamically only for item, rarity, artifact, symbol and tier ids (`items.*`, `rarity.*`, `artifacts.*`, `symbols.*`, `tiers.*`). Polish grammar does not bend around placeholders: write lines so a name or number fits without changing case.
- **Editing from the shell:** backticks and `${}` in JS template literals are eaten by Bash inside `node -e "..."` and `$(...)`. Write patch scripts to a file in the scratchpad and run that, or use the Edit tool.
